01 · TRIAGEIA Salud Digital

Entra quien está más grave

Sala de espera en tiempo real, ingreso de pacientes con registro de signos y foto clínica, estadísticas de demanda y generación automatizada del reporte de turno. Diseñado para optimizar los flujos entre enfermería y administración.

Qué hace

Operatividad
  • Ordena la cola por puntaje: Clasificación dinámica basada en severidad médica y nunca por orden de llegada.
  • Gestión del turno: Pasa a atención médica, consulta de historial clínico y auditoría de turno.
  • Pantalla y avisos: Visualización pública de sala en vivo y notificación directa del turno vía WhatsApp.
🔑 Acceso Administrador: Usuario: admin Clave: 12345678

Cómo decide

Algoritmo Clínico
  • Puntaje 0–100: Fusión algorítmica de los protocolos estandarizados ESI (Emergency Severity Index) y NEWS2.
  • Cinco niveles de atención: Estratificación formal desde prioridad Crítica hasta prioridad Mínima.
  • Regla de desempate: Ante puntajes idénticos, tiene prioridad inmediata el paciente de 65 años o más.

01 · TRIAGEIA Herramientas & Infraestructura

React, Spring y Azure

React 18 + Vite Spring Boot 3.3 · Java 17 5 microservicios + API Gateway REST + SSE + gRPC HTTP/2 PostgreSQL (Supabase) Vercel + Azure Container Apps Gemini ➔ Fallback Claude Haiku 5.5

Cómo se habla

Protocolos
  • Cliente navegador: Consume endpoints REST estándar para autenticación y gestión de pacientes.
  • Sala en vivo con SSE: Server-Sent Events (EventSource) empuja las actualizaciones de la cola al instante sin polling.
  • Malla interna con gRPC: Comunicación HTTP/2 de alto rendimiento y serialización binaria entre los microservicios.

Dónde vive

Despliegue
  • Frontend en Vercel: Distribución global perimetral para máxima velocidad de carga en sala.
  • Backend en Azure Container Apps: Región Brasil South (resource group: triage-brazilsouth) ejecutando: api-gateway, ms-pacientes-auth, ms-evaluacion-triaje, ms-cola-espera y ms-ia-recomendacion.
  • Persistencia y DNS: Base de datos en Supabase y gestión de subdominios bajo Porkbun.

02 · HOSPY Ecosistema Hospitalario

Tecnología que conecta con los corazones

Portal hospitalario unificado con tres roles interactivos: paciente, médico y administrador. Centraliza agendamiento inteligente de citas, avisos en vivo, asistente clínico asistido por IA y farmacia triangulada.

Paciente

Rol 1

Agenda y sigue su atención:

  • Reserva citas médicas en tiempo real según la especialidad requerida.
  • Consulta recetas electrónicas emitidas y estado de sus exámenes.
  • Recibe alertas instantáneas en vivo sobre el llamado a su consulta.

Médico

Rol 2

Consulta, receta, orientación:

  • Atención clínica interactiva con visualización de antecedentes médicos.
  • Generación y firma digital de recetas y órdenes médicas.
  • Asistente inteligente para orientación diagnóstica y prevención de interacciones.

Admin

Rol 3

Cuentas, reportes, especialidades:

  • Control centralizado de usuarios médicos, pacientes y roles RBAC.
  • Estadísticas de demanda asistencial y métricas de tiempos de espera.
  • Configuración del catálogo de especialidades y módulos de farmacia.

02 · HOSPY Herramientas & Monolito

Angular, Spring y WebSocket

Angular 21 Spring Boot 4 · Java 21 Monolito Modular REST + WebSocket (/api/live) JWT + Spring Security PostgreSQL 16 Redis (Opcional multi-nodo) Vercel + Docker en Render Cascada IA: Gemini ➔ Haiku ➔ OpenAI

Tiempo real

WebSocket
  • Canal WebSocket /api/live: Conexión persistente y bidireccional que actúa como el timbre digital de llamado a consulta.
  • Avisos instantáneos: Empuja eventos en tiempo real hacia los paneles de médicos y pacientes sin retardos.
  • Redis Pub/Sub: Soporte opcional preparado para sincronización de estados si se despliega más de un servidor backend.

Un solo backend

Arquitectura Robusta
  • Monolito modular: Spring Boot 4 y Java 21 estructurado en módulos desacoplados, evitando la complejidad innecesaria de microservicios.
  • Seguridad con JWT: Autenticación sin estado gestionada mediante filtros de Spring Security y PostgreSQL 16.
  • Despliegue ágil: Frontend Angular en la red global de Vercel y API empaquetada en contenedor Docker alojado en Render.

03 · ECOSCAN Inteligencia Ambiental

Tu aliado en el reciclaje inteligente

Subes la foto del residuo y el sistema identifica el material, indica el contenedor exacto, provee los pasos de separación limpia y calcula el impacto ecológico. Aulas colaborativas, ranking y un planeta 3D interactivo que se gira.

Qué hace

Funcionalidades
  • Clasifica con foto: Reconocimiento instantáneo de plásticos, metales, vidrio, papel y residuos orgánicos.
  • Guía de separación: Pasos claros para limpiar, plegar y depositar el material sin contaminar el flujo de reciclaje.
  • Historial y aulas: Registro de impacto personal, comunidades de clase con rankings y planeta 3D explorable.

Cómo clasifica

Visión Híbrida
  • Foto del residuo: Captura directa con la cámara del dispositivo móvil o carga de imagen desde el navegador.
  • Modelo ONNX en el dispositivo: Inferencia local ejecutada en el propio celular/computador para respuesta ultra-rápida.
  • Fallback con IA en servidor: Ante dudas o imágenes complejas, consulta de respaldo con Gemini o Claude Haiku.

03 · ECOSCAN Herramientas & Visión

React, FastAPI y visión

React 18 + TypeScript + Vite FastAPI (Python, Uvicorn) REST API ONNX en Web Worker Leaflet (Puntos Verdes) PostgreSQL (Supabase) · SQLite local Vercel + Render Gemini Fallback ➔ Haiku

Visión

Inferencia en el Borde
  • Web Worker con ONNX: La red neuronal corre en un hilo secundario del navegador; clasificación en milisegundos sin latencia de red.
  • Resiliencia con IA generativa: Si el modelo del dispositivo no alcanza la certeza requerida, el servidor completa la visión con Gemini o Haiku.
  • Mapeo interactivo: Mapas integrados con Leaflet para ubicar contenedores y puntos limpios de reciclaje comunitarios.

Datos

Persistencia Flexible
  • PostgreSQL en Supabase: Tablas estructuradas para users, scans y classrooms con métricas de impacto.
  • Fallback SQLite local: Capacidad de operar sin URL de conexión en entornos locales o de demostración académica.
  • Despliegue perimetral: Frontend servido en Vercel y servicio API Python ASGI en contenedor Render.
